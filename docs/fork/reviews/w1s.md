# W1-S — lead review of 2830a770 (binding)

Direction is right (one admission classifier, receipt inside Live/Woken, capability under initialize `_meta`, root path unchanged). Not integrable yet:

1. **Re-pairing admission with host is an invalid state made representable.** `prompt()` classifies from `session_host`, then matches `(admission, session_host)` again and returns `internal_error("session admission host changed")` for impossible pairs. Carry the host inside the admission instead (`PromptAdmission::Child { host: ChildHost, admission: ChildPromptAdmission }` or the receipt-bearing variants hold what the send needs), so the send site needs no second match and no impossible arms.
2. **`PromptAdmission::Unknown` duplicates `Option<SessionHost>::None`.** Unknown session is an error at the boundary; return it from the classifier (`Err(unknown session id)`) and drop the variant.
3. **`ChildTurnSink.closed: Arc<AtomicBool>` is derived state beside its source.** The mpsc sender already knows whether the drain is gone (`Sender::is_closed()`); `finish_child_turn_sink` + `release_child_session` run back-to-back, so the flag never distinguishes anything a prompt can observe. Model the lifecycle where it lives: the registry entry of a finished child is a typed state (e.g. `SessionPresence`/host variant `ChildFinished { parent_session_id, subagent_id, owner }`), set on release instead of removing the host. Then: resident child → `Live`; finished known child → `Woken` (same identity, T/task/coordinator/wake.rs) ; unknown after restart → `ContinuedAs` via M4 `human_resume_request`. No atomic flag.
4. **`Woken` and `ContinuedAs` must execute, not refuse.** Today `ContinuedAs` returns `internal_error(... must be resolved by resume admission)` and `Woken` just sends a receipt into a closed sink (it would fail with `try_send`). Wire both per design §4 “Shell behavior” (wake.rs L54-146 same-id wake; resume.rs L225-249 human_resume_request). If wiring one of them needs a coordinator API that does not exist, stop and write the exact question with file:line evidence.
5. **Leader `child_routes: HashMap<String, ChildRoute>` is written but never read** for any routing decision (`Finished` is inserted and never consulted) — dead state. Either the route state decides something (e.g. a finished child's prompt/load is still routed to the parent's driver and pruned only when the parent session closes, per design) or it goes. Also `SubagentFinished` no longer prunes at all: confirm pruning happens when the parent session closes (the current removal at server.rs ~1679 keys on the child's own subscribers) — no unbounded growth.
6. **Receipt telemetry:** `ActiveAgentMessageAdmissionTelemetry::new(.., Queue, Queue, None)` is a guessed value and misformatted. Use the operation the prompt really performs (human prompt to child = the existing human-message operation if one exists; otherwise add the variant) and rustfmt the file.
7. `let _ = completion.send(stop_result.clone())`: fine only if a dropped receiver is a legitimate outcome (parent already gone); name that in the match instead of discarding silently if the coordinator distinguishes it.
8. Rebase onto current main before the next commit (base is `f6b45711`, main is `3b54b425`).

Tests: only behavior tests that pin the admission outcomes (resident child prompt reaches the child and the parent receives the child's last response; finished child wakes with the same id; workflow child refused). No tests that mirror implementation.
