# F6/F7 design — grok-build `main` (read-only)

Paths below are relative to `crates/codegen/`: P=`xai-grok-pager/src`, S=`xai-grok-shell/src`, C=`xai-chat-state/src`, A=`xai-grok-agent/src`, ST=`xai-grok-sampling-types/src`. M5 evidence is from the uncommitted `grb-m5` worktree; it is **not** in main. No builds were run.

## 1. What reaches the main model today

The actual normal-turn path is `S/session/acp_session_impl/turn.rs:2824,2860-2890,2914-2973,2990-3051`: prepare tools, optionally compact, inject reminders, `chat_state_handle.build_request(effective_tools, memory_reminder, …)`, add hosted tools/schema/metadata, `run_turn_via_sampler`. `C/handle.rs:413-430` sends that command to the chat-state actor; `C/actor/request_builder.rs:20-103` clones canonical history, budgets old images, prunes old tool-result bodies, injects memory, projects via `ModelRequestHistory::from_raw`, then creates `ConversationRequest { items, tools }`. `C/actor/state.rs:35-100` owns existing bytes/4 + image/tool/reasoning estimates; these are approximations, not exact provider tokens. `ST/conversation.rs:68-85,101-170` defines item origins and the model-facing variant set. `ST/conversation/responses.rs:4,13-86,136-142,243-271` preserves provider reasoning/interleaving and forwards prompt-cache metadata. **Do not use the pager's scrollback as the request source**: UI blocks do not map one-to-one onto these items.

Closed **user-facing projection** of context categories (`ContextCategory`; **every category is switchable**, `Included | Excluded`, per session). The only non-category invariant is the *currently submitted prompt* (text and attachments): without that input there is no user turn to submit (`S/session/acp_session_impl/prompt_build.rs:819-909`, `S/session/acp_session_impl/turn.rs:2950-2973`). Historical prompts remain switchable. “Size” is cached/updated at construction or on request snapshot, never recounted in `draw`; when data are not yet loaded show `—`, not zero. The category classifier must cover every `ConversationItem`/`SyntheticReason`/tool source exhaustively; wire `Unknown` remains visible as `OtherRuntime` and defaults included.

## 2. Opt-out model and request seam

**Scope**: per session, persistent across resume, inherited only as a snapshot when forking a child (thereafter independent). Context choices must travel with the shell session ID because shell also serves CLI/headless requests; pager.toml is a global **appearance** owner (`P/settings/registry.rs:17-25`, `P/scrollback/types.rs:105`), not authority over server-side request content. New session defaults `Included` for all categories; only the current prompt/attachments are a non-category request invariant. CoreInstructions, ProjectInstructions, ToolDefinitions, Reasoning and every RuntimeNotice origin can be excluded, with explicit consequences. Store the typed `ContextPolicy` with session metadata/history in the existing shell session storage owner, write only on edit, load with normal resume (no default-path extra I/O), expose an ACP `x.ai/session/context_policy` get/set + changed notification so all pager views, including children, reflect shell truth. On spawn inherit policy explicitly via the existing child creation parameters; do **not** gate by root/child view or use process-global settings. Use `ContextSwitch::{Included,Excluded}` per exhaustive `ContextCategory` (with typed notice subcategories where necessary); **no Locked state**. `ToolExchange(ContextItemRef)` applies only when addressing an individual item. The warning is a derived projection of category and state, not a third control state. `ContextItemRef` from M5 is reused, not copied. Per-item opt-out is separate `ContextInclusion::{Included,Excluded}` keyed by M5's `Turn { prompt_index } | ToolExchange { tool_call_id }` and expires when the source is deleted/compacted; category switch composes with item switch without storing derived state.

**One request projection** in `C/actor/request_builder.rs:20-103`, after image budget/pruning and memory assembly, before `ModelRequestHistory::from_raw` and `ConversationRequest` construction. Pass a compact typed policy snapshot in `C/commands.rs`/`C/handle.rs:413-430` from `S/session/acp_session_impl/turn.rs:2950-2973`; perform at most one linear pass already inside the O(history) clone/build. Preserve canonical conversation and replay unmodified. Better: classify and store per-item provenance/token estimate on the chat-state actor's append/replace boundary; request projection reads metadata once instead of re-parsing whole prompt or hashing text on each turn. The existing `ModelRequestHistory` projection is the owner of provider-safe adjacency: compose the filter with it, *before* its repair/normalization, preserving assistant tool-call IDs and matching tool results, backend call/reasoning sibling order, and cache-breakpoint assumptions. Keep excluded call/result as a provider-valid neutral result when needed, rather than deleting just ToolResult; if neutralization cannot preserve a backend protocol, project the complete typed exchange out instead, retaining only the provider-required neutral placeholder; test both provider mappings. Never splice inside opaque encrypted reasoning: remove its whole provider reasoning item with associated response-envelope normalization. Turning off ToolDefinitions also removes hosted tools and coordinates schema/tool-choice/structured-output capability; a warning says tool use may fail or be unavailable, but the switch remains effective. Policy change mid-sample affects the **next build**, never an already submitted request. Changing early prefix invalidates provider prompt-cache prefix; display `cache reset` and measure it; do not rewrite persisted history merely to control a request.

**M5 is irreversible removal** and changes both durable conversation and replay UI. M5 worktree `S/session/remove_items.rs:4-20` defines refs/outcomes, `S/session/acp_session_impl/remove_items.rs:4-57` mutates history, `P/app/agent_view/context_removal.rs:7-27` currently resolves only UserPrompt/group UserPrompt refs (not tools); finish M5 identity/pairing before opt-out. An excluded item remains visible, annotated `not sent` in F6/F7/chat; `d` uses M5 and removes it from both state and policy references only after acknowledged success. M5 currently scans item-by-item and `remove_items_from_conversation` drops whole Assistant items if *any* call ID matches (`…/remove_items.rs:101-110`): this risks deleting unrelated parallel calls and leaving their results. Fix that pair-integrity root cause in M5 first; reuse the corrected exchange classifier in opt-out. M5's `BeforeCompaction` applies only to delete: after compaction, F7 sees only the summary, not vanished source items. Future compaction must summarize **effective included** context (same projection), or excluded secrets will re-enter via summary; keep historical source/replay as-is. Special auxiliary calls (compact, goal classifier, summarizer, side calls at `S/session/acp_session_impl/side_call.rs:170`, `S/session/compaction.rs:139-169`) must use the same policy projection or state an explicit typed purpose-specific policy and not silently leak excluded content.

## 3. One display-form model

`P/scrollback/block.rs:298-323` owns actual `RenderBlock` variants: Stub(test-only), UserPrompt, AgentMessage, ToolCall, Thinking, System, SessionEvent, BgTask, Subagent, Workflow, Btw, ContextInfo, MemoryCapture(debug). `P/scrollback/blocks/tool/mod.rs:149-167` subdivides ToolCall into Execute, Read, Edit, ListDir, Search, WebFetch, WebSearch, IntegrationSearch, UseTool, MemorySearch, SentMessage, Skill, Other. A single exhaustive `MessageKind::from(&RenderBlock)` classifier should keep the **same** ToolKind distinctions where form differs; Stub remains internal, never a settings row. Do not conflate context category and display kind; e.g. ContextInfo is UI-only and not sent. `P/scrollback/types.rs:60-68` currently has `DisplayMode::{Collapsed,Truncated,Expanded}`; `P/scrollback/block.rs:82-114` allows custom finish/running modes. F7 exposes only `DisplayForm::{Collapsed,Expanded}`. Collapsed means **one visible row including badge/ellipsis at every width**; expanded means full unbounded body (except viewport scrolling), including failed subagent error body. `Truncated` is a preexisting streaming/pinned-header presentation, **not** a third selectable F7 form; user prompt `Truncated` uses one line for a foldable prompt (`P/scrollback/blocks/user.rs:450-460`) and M7 retains a three-line *foldability threshold* (`user.rs:493-510`). Never route F7 collapse through `collapse_mode()` (Execute running returns Truncated) or `is_foldable()` (Subagent false, `subagent.rs:290-295`): explicit form applies to all kinds. Keep `Truncated` only in a separately named internal transient/pinned display state, with conversion to the selected binary default at completion; preserve manually requested per-entry form as `EntryForm::{FollowingKind,Override(DisplayForm)}` (or equivalent provenance), so a changed kind default updates followers and does not erase manual folds (`respect_manual_folds`). Group disclosure is independent. Apply newly changed kind defaults on edit with one batch remeasure/`invalidate_heights`, not in frame draw (`P/scrollback/state/mod.rs:375-399`); cache one-line output/height keyed by width, content generation, appearance, kind form, selection and active state using existing entry cache (`P/scrollback/entry.rs:465-499`). Render only visible entries and F7 visible rows. Existing thinking hide toggle (`P/scrollback/entry.rs:482-488`) stays an independent explicit visibility concern, **not** an implicit third form.

Display defaults are global pager appearance persisted through existing pager.toml appearance load/write and live settings cache; per-block overrides are session-view state as today (not promised across resume). No new session file or session/global layering unless explicitly requested; no extra startup read. The presence of unfodable subagents, always-collapsed BgTask, tool output layouts and vpad means this is a cross-renderer contract change, not merely relabeling `DisplayMode`.

## Faruk decision: layout (binding; supersedes the width policy, narrow overlay and "header/prompt full width" in §4/§5 and the mockups)

Faruk (verbatim): "für die sidebars F6/F7 will ich einfach nur dass das layout nicht abgefuckt wird, sondern alles nach normalen UI Standards korrekt positioniert und floatet, wenn F6 und F7 aktiviert ist, dann soll es ein 3-Spalten layout sein, ca 50% für die mitte (das was jetzt 100% hat) und rest für die sidebars links und rechts". Also: "ich will überhaupt nichts besonderes, sondern einfach nur das was schon da ist".

- **Three columns.** The center column holds the complete current session view: header, transcript, composer and hint row, i.e. everything that fills 100% today. F6 is a full-height column on the left and F7 a full-height column on the right.
- **Widths:**
  - both open: about 25% | 50% | 25%;
  - one open: 35% sidebar and 65% center (F6 left, or F7 right);
  - both closed: the center at 100%, exactly as today.
  All values are recomputed on resize, with no overlay mode and no special narrow-terminal behavior.
- **One sidebar component (Faruk, after seeing the PNGs).** F6 and F7 are two instances of the SAME sidebar component, so later adjustments benefit both equally. The component owns:
  - **Header:** fixed, does not scroll. Its height equals the current session header's top row only (one row). The dock/subagent area moves into F7 and is not part of the header height.
  - **Body:** scrollable, with a scrollbar when the content exceeds the height.
  - **Footer:** fixed, does not scroll. Its height equals the chat composer in its initial empty state.
  - Border, background, focus and hover styling, the scroll state, and the one row-detail popup.
  - F6 and F7 supply only their body rows plus the header/footer content.
- **F7 body** is one column with the sections stacked vertically: Dock, then Context, then Message Display. No side-by-side sub-columns.
- **The dock is reused as it is (Faruk).** Verbatim: "der dock zeichnet nicht nur subagents, sondern auch monitors und tasks und weitere, es soll einfach nur in der sidebar leicht optimiert wiederverwendet werden so wie es ist".
  - The entire existing dock (every section: Workflows, Subagents, Tasks, Watchers/Monitors, Queued, …) is hosted in F7 through its own renderer: `dock::desired_height` + `dock::render`.
  - Nothing is re-modeled.
  - The narrow-width adaptation (glyphs for wide labels, full text on hover) is a small change inside the existing dock renderer, owned by B4.
  - The F6 timeline is hosted the same way through its existing renderer.
- **Content inside the center column** lays out exactly as the view does today at that width. The sidebars are ordinary bordered columns that follow the normal UI conventions of the existing app: the same background, borders and colors as the rest of grok.
- **Visual rework stays minimal.** Reuse what exists. The visual spec above only applies where the current F6 rendering is broken (rail placement, row noise). There are no new visual concepts.

## Visual spec — shared chat language, not a second transcript theme

**Screenshot defects and cause.** The rail screenshot (`screenshots/f6-rail-before.png`) shows a detached narrow strip: ▲/▼ far apart, uniform thin ticks, an outsized bright active stroke, and a dead-looking gutter. `P/views/timeline.rs:195-251` centers the tick stack in the *whole* scrollback, gives idle ticks a hard-coded light stroke, brightens active to `theme.text_primary` with a two-cell bar and positions the chevrons independently; `P/views/agent.rs:363-381` reserves it on the right as a scrollbar replacement. Display summary text is precomputed on outline generation and refreshed on structural change (`P/views/timeline_panel.rs:88-117`), not format/path-transform per frame. ## 7. Risks / decisions

- **Source-truth gap, binding decision (b)**: existing rendered prefix/System and reserved-but-untagged synthetic origins make per-section exclusions impossible by merely filtering conversation variants (`ST/conversation.rs:160-169`; `S/session/acp_session_impl/prompt_build.rs:525-675`). A1/A2 are mandatory architecture repair **before F7 ships**: every category, including core/project instructions, tool definitions, reasoning and runtime notices, is switchable; warnings state consequences without overriding user choice. No locked or inert category. The current prompt/attachments alone remain outside the category set because they constitute this request. Provider-required pair placeholders are structural protocol, not retained opted-out content. Disabling all instructions/tools can make the agent ineffective; that is an explicit warning, not a reason to silently re-enable them.
- **M5 risk**: tool IDs are strings in its current implementation, and it drops entire assistant items containing any selected call (`grb-m5/S/session/acp_session_impl/remove_items.rs:101-110`). Fix first, retain siblings and provider-valid pairs; ensure display also resolves actual ToolExchange refs (`grb-m5/P/app/agent_view/context_removal.rs:7-27`). M5's marker/replay and the optional exclusion marker are different: no extra replay marker for a reversible request-only policy.
- **Compaction and auxiliary samplers**: source excluded from the next user turn must not leak through compaction summaries/fork or an auxiliary sampler. Routing them through the policy is mandatory, including auxiliary/compaction request assembly; otherwise an OFF switch would be false advertising. Earlier summaries cannot be decomposed after compaction.
- **Dock/queue regression risk**: `P/views/dock/mod.rs:77-95,179-180,236-252` and `P/views/dock/layout.rs:94-133` put Queued inside the dock, but `P/app/agent_view/render.rs:1011-1027,1878-1892` can still render the same queue by the composer when dock mode is off. After B4, F7 closed must hide **both** placements while preserving pending prompts and composer commands; F7 open must preserve the Queued body's existing Send now/edit/cancel actions and stop confirmation. `dock_enabled` and short-terminal policy must not silently resurrect an old dock or hide queued work without an F7 affordance. Existing `paint_row` drops text via `truncate_line` (`P/views/dock/mod.rs:451-468`): only compact the line when the full row is available via hover/keyboard-selected detail, and keep `[↗]`/`[X]` hittable. Cache geometry and clear stale hover/action rects on close/resize; otherwise clicks can target an invisible dock.
- **Plan supersession**: this replaces S-A's four user forms/Hidden/capped/click-chord cycle with **two** kind defaults (collapsed=one line, expanded=full) plus internal Truncated; S-B's right-click bulk gesture, hover-tokens and global/session layering with a focused F7 `Dock + Context + Message Display` menu and session-owned context/global pager appearance; S-M's optional per-kind switches become explicitly required as the F7 display rows. S-I finer assistant/reasoning delete and palette generation stay deferred; M5 delete is reused, not reimplemented. Existing plan text and the subagent design conflict on E5/child gates; owner should reconcile before executing waves (documentation current-truth gate).
- **Decision settled by Faruk: (b)** every context category, even `<always_applied_workspace_rules>` (`A/prompt/user_message.rs:52-66`), can be OFF per session. Do not reintroduce a governance lock or a shadow copy in System/first-user preamble; display a concise warning that excluding these rules changes behavior. **Visual acceptance risk**: moving a flat/right-aligned list to the left would retain the defects visible in both screenshots. Wave D must demonstrate chat-consistent semantic hierarchy, left-flush integrated rail and right-hand scrollbar using rendered-buffer tests, rather than considering placement alone sufficient.
