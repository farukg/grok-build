# F6/F7 design — grok-build `main`

## User scope and presentation preferences

Shared UI state generally belongs to the global scope and remains stable across session switches. Drafts, experiments and deliberate departures from defaults generally belong to a session. Each setting offers the scopes needed for its actual use; both scopes are not required everywhere. Resolve later scope questions against this preference. F7 group disclosure is global independently of the Context-policy and Message-display scopes.

Compact history rows should reuse native kind glyphs instead of repetitive Read/Search text prefixes, share the existing timestamp/date renderer, align meaningful columns through the existing layout, and use available width before truncating. Expanded shows substantive content. Harness activity and model inclusion remain discoverable in normal history through subdued gutter/kind markers and hover/Enter details. Permanent per-row labels, verbose suffixes and repeated explanatory text are excluded from the normal transcript; request inspection supplies the detail. These presentation and request-inspection requirements are tracked in the active Grok F7/request-display plan; the source-specific sections below state which parts currently exist.

Paths below are relative to `crates/codegen/`: P=`xai-grok-pager/src`, S=`xai-grok-shell/src`, C=`xai-chat-state/src`, A=`xai-grok-agent/src`, ST=`xai-grok-sampling-types/src`. M5 (context removal) is on `main`; §2 describes its current state.

## 2. Opt-out model and request seam

**Scope contract**: independently selectable Global/Session and persistent across resume. Global changes warn and offer the Session alternative; Context scope switches warn in both directions. Global policy belongs to the leader and applies to its followers and new sessions; Session deviations remain separate. The current Shell source remains session-only while the global/warning path is implemented. Context choices must travel with the shell session ID because shell also serves CLI/headless requests; pager.toml is a global **appearance** owner (`P/settings/registry.rs:17-25`, `P/scrollback/types.rs:105`), not authority over server-side request content. New session defaults `Included` for all categories; only the current prompt/attachments are a non-category request invariant. CoreInstructions, ProjectInstructions, ToolDefinitions, Reasoning and every RuntimeNotice origin can be excluded, with explicit consequences. Store the typed `ContextPolicy` with session metadata/history in the existing shell session storage owner, write only on edit, load with normal resume (no default-path extra I/O), expose an ACP `x.ai/session/context_policy` get/set + changed notification so all pager views, including children, reflect shell truth. On spawn inherit policy explicitly via the existing child creation parameters; do **not** gate by root/child view or use process-global settings. Use `ContextSwitch::{Included,Excluded}` per exhaustive `ContextCategory` (with typed notice subcategories where necessary); **no Locked state**. `ToolExchange(ContextItemRef)` applies only when addressing an individual item. The warning is a derived projection of category and state, not a third control state. `ContextItemRef` from M5 is reused, not copied. Per-item opt-out is separate `ContextInclusion::{Included,Excluded}` keyed by M5's `Turn { prompt_index } | ToolExchange { tool_call_id }` and expires when the source is deleted/compacted; category switch composes with item switch without storing derived state.

**One request projection** in `C/actor/request_builder.rs:20-103`, after image budget/pruning and memory assembly, before `ModelRequestHistory::from_raw` and `ConversationRequest` construction. Pass a compact typed policy snapshot in `C/commands.rs`/`C/handle.rs:413-430` from `S/session/acp_session_impl/turn.rs:2950-2973`; perform at most one linear pass already inside the O(history) clone/build. Preserve canonical conversation and replay unmodified. Better: classify and store per-item provenance/token estimate on the chat-state actor's append/replace boundary; request projection reads metadata once instead of re-parsing whole prompt or hashing text on each turn. The existing `ModelRequestHistory` projection is the owner of provider-safe adjacency: compose the filter with it, *before* its repair/normalization, preserving assistant tool-call IDs and matching tool results, backend call/reasoning sibling order, and cache-breakpoint assumptions. Keep excluded call/result as a provider-valid neutral result when needed, rather than deleting just ToolResult; if neutralization cannot preserve a backend protocol, project the complete typed exchange out instead, retaining only the provider-required neutral placeholder; test both provider mappings. Never splice inside opaque encrypted reasoning: remove its whole provider reasoning item with associated response-envelope normalization. Turning off ToolDefinitions also removes hosted tools and coordinates schema/tool-choice/structured-output capability; a warning says tool use may fail or be unavailable, but the switch remains effective. Policy change mid-sample affects the **next build**, never an already submitted request. Changing early prefix invalidates provider prompt-cache prefix; display `cache reset` and measure it; do not rewrite persisted history merely to control a request.

**M5 is irreversible removal** and changes both durable conversation and replay UI. `S/session/remove_items.rs` defines the refs and the outcome (`Removed { removed, skipped }`, `TurnRunning`, `NotFound`, `BeforeCompaction`, `WouldOrphan`, `PersistFailed { removed }`); `S/session/storage/remove_filter.rs` classifies each ref once (a removed tool exchange keeps its parallel siblings and the assistant text; a removed backend call takes its sealed reasoning blob with it) and `S/session/acp_session_impl/remove_items.rs` makes the rewrite durable before it writes the replay marker. The pager decides before sending (`P/app/agent_view/removal_verdict.rs`: a row is removable or the verdict names why not) and then removes exactly the rows the shell reports. An excluded item remains visible, annotated `not sent` in F6/F7/chat; `d` uses M5 and removes it from both state and policy references only after acknowledged success. Opt-out reuses the exchange classifier of `remove_filter.rs`. M5's `BeforeCompaction` applies only to delete: after compaction, F7 sees only the summary, not vanished source items. Future compaction must summarize **effective included** context (same projection), or excluded secrets will re-enter via summary; keep historical source/replay as-is. Special auxiliary calls (compact, goal classifier, summarizer, side calls at `S/session/acp_session_impl/side_call.rs:170`, `S/session/compaction.rs:139-169`) must use the same policy projection or state an explicit typed purpose-specific policy and not silently leak excluded content.

## 3. One display-form model

`P/scrollback/block.rs:298-323` owns actual `RenderBlock` variants: Stub(test-only), UserPrompt, AgentMessage, ToolCall, Thinking, System, SessionEvent, BgTask, Subagent, Workflow, Btw, ContextInfo, MemoryCapture(debug). `P/scrollback/blocks/tool/mod.rs:149-167` subdivides ToolCall into Execute, Read, Edit, ListDir, Search, WebFetch, WebSearch, IntegrationSearch, UseTool, MemorySearch, SentMessage, Skill, Other. A single exhaustive `MessageKind::from(&RenderBlock)` classifier should keep the **same** ToolKind distinctions where form differs; Stub remains internal, never a settings row. Do not conflate context category and display kind; e.g. ContextInfo is UI-only and not sent. `P/scrollback/types.rs:60-68` currently has `DisplayMode::{Collapsed,Truncated,Expanded}`; `P/scrollback/block.rs:82-114` allows custom finish/running modes. F7 exposes only `DisplayForm::{Collapsed,Expanded}`. Collapsed means **one visible row including badge/ellipsis at every width**; expanded means full unbounded body (except viewport scrolling), including failed subagent error body. `Truncated` is a preexisting streaming/pinned-header presentation, **not** a third selectable F7 form; user prompt `Truncated` uses one line for a foldable prompt (`P/scrollback/blocks/user.rs:450-460`) and M7 retains a three-line *foldability threshold* (`user.rs:493-510`). Never route F7 collapse through `collapse_mode()` (Execute running returns Truncated) or `is_foldable()`: explicit form applies to all kinds, regardless of producer foldability hints. Keep `Truncated` only in a separately named internal transient/pinned display state, with conversion to the selected binary default at completion; preserve manually requested per-entry form as `EntryForm::{FollowingKind,Override(DisplayForm)}` (or equivalent provenance), so unrelated default changes preserve manual folds; explicitly reapplying a kind value or changing the effective Display scope reapplies the selected values to the affected entries. Group disclosure is independent. Apply newly changed kind defaults on edit with one batch remeasure/`invalidate_heights`, not in frame draw (`P/scrollback/state/mod.rs:375-399`); cache one-line output/height keyed by width, content generation, appearance, kind form, selection and active state using existing entry cache (`P/scrollback/entry.rs:465-499`). Render only visible entries and F7 visible rows. Existing thinking hide toggle (`P/scrollback/entry.rs:482-488`) stays an independent explicit visibility concern, **not** an implicit third form.

Display defaults are saved by the pager in `<grok home>/panel-settings/global.toml` and `sessions/<session id>.toml` (module `app/panel_settings`). The session file's `scope.message_display` chooses the effective Global or Session values. Global uses global then built-in values; Session uses session, global, then built-in values. New sessions use Global; legacy session form overrides retain their Session scope until an explicit choice is saved. F7 section folds are global-only and are applied across loaded sessions; legacy session section values are ignored with a load warning. An F7 display edit uses the selected effective scope. Changing `g` persists that scope in the session file and immediately reapplies its stored values; switching back restores the other scope's values. A form the user set is stored as chosen (a kind nobody set renders by its block's own policy, which is not one form); per-block overrides stay session-view state. Subagent and BgTask compact summaries are not a substitute for expanded content. Their local description/command/metadata preambles now wrap fully, but canonical BgTask stdout and child-transcript projections are still pending separate owner integration (F2/F3). Foldability must include those projections once attached, including empty/running/failed/replayed cases. Tool output layouts and vpad make this a cross-renderer contract change, not merely relabeling `DisplayMode`.


Renderer contract (2026-10-27, source only): compact headers use the shared native kind glyph owner, including Skill, WebSearch (retaining X identity), integration discovery, Edit/create, command-label and lifecycle rows. `$`, provider/action identity and meaningful status/duration data remain. Group-summary verbs are not individual type prefixes. Every compact entry with a captured timestamp uses the existing EntryRenderer timestamp gutter and hover-date overlay, subject to its existing appearance/width gates. Expanded bodies retain full source text through shared wrapping/joiners; presentation indentation is excluded from selection. WebFetch/WebSearch/UseTool share one content-box owner; per-kind headers, arguments, sources and error conditions remain distinct. No runtime, visual or build acceptance is implied.

## Faruk decision: layout (binding; supersedes the width policy, narrow overlay and "header/prompt full width" in §4/§5 and the mockups)

Faruk (verbatim): "für die sidebars F6/F7 will ich einfach nur dass das layout nicht abgefuckt wird, sondern alles nach normalen UI Standards korrekt positioniert und floatet, wenn F6 und F7 aktiviert ist, dann soll es ein 3-Spalten layout sein, ca 50% für die mitte (das was jetzt 100% hat) und rest für die sidebars links und rechts". Also: "ich will überhaupt nichts besonderes, sondern einfach nur das was schon da ist".

- **Three columns.** The center column holds the complete current session view: header, transcript, composer and hint row, i.e. everything that fills 100% today. F6 is a full-height column on the left and F7 a full-height column on the right.
- **Widths:**
  - both open: about 25% | 50% | 25%;
  - one open: 35% sidebar and 65% center (F6 left, or F7 right);
  - both closed: the center at 100%, exactly as today.
  All values are recomputed on resize, with no overlay mode and no special narrow-terminal behavior.
- **One sidebar component (Faruk, after seeing the PNGs).** F6 and F7 are two instances of the SAME sidebar component, so later adjustments benefit both equally. The component owns:
  - **Header:** fixed, does not scroll. Its height equals the current session header's top row only (one row). The dock/subagent area moves into F7 and is not part of the header height.
  - **Body:** scrollable, with a scrollbar when the content exceeds the height.
  - **Footer:** fixed, does not scroll. Its height equals the chat composer in its initial empty state.
  - Border, background, focus and hover styling, the scroll state, and the one row-detail popup.
  - F6 and F7 supply only their body rows plus the header/footer content.
- **F7 body** is one column with the sections stacked vertically: Dock, then Context, then Message Display. No side-by-side sub-columns.
- **The dock is reused as it is (Faruk).** Verbatim: "der dock zeichnet nicht nur subagents, sondern auch monitors und tasks und weitere, es soll einfach nur in der sidebar leicht optimiert wiederverwendet werden so wie es ist".

  - Nothing is re-modeled.
  - The narrow-width adaptation (glyphs for wide labels, full text on hover) is a small change inside the existing dock renderer, owned by B4.
  - The F6 timeline is hosted the same way through its existing renderer.
- **Content inside the center column** lays out exactly as the view does today at that width. The sidebars are ordinary bordered columns that follow the normal UI conventions of the existing app: the same background, borders and colors as the rest of grok.
- **Visual rework stays minimal.** Reuse what exists. The visual spec above only applies where the current F6 rendering is broken (rail placement, row noise). There are no new visual concepts.

## 7. Risks / decisions

- **Source-truth gap, binding decision (b)**: existing rendered prefix/System and reserved-but-untagged synthetic origins make per-section exclusions impossible by merely filtering conversation variants (`ST/conversation.rs:160-169`; `S/session/acp_session_impl/prompt_build.rs:525-675`). No locked or inert category. The current prompt/attachments alone remain outside the category set because they constitute this request. Provider-required pair placeholders are structural protocol, not retained opted-out content. Disabling all instructions/tools can make the agent ineffective; that is an explicit warning, not a reason to silently re-enable them.
- **M5 and opt-out**: M5's marker/replay and the optional exclusion marker are different: no extra replay marker for a reversible request-only policy. Open in the removal path: the rewind picker still lists removed turns, and a two-pass compaction prefire is not invalidated by a removal.
- **Compaction and auxiliary samplers**: source excluded from the next user turn must not leak through compaction summaries/fork or an auxiliary sampler. Routing them through the policy is mandatory, including auxiliary/compaction request assembly; otherwise an OFF switch would be false advertising. Earlier summaries cannot be decomposed after compaction.
- **Dock/queue regression risk**: `P/views/dock/mod.rs:77-95,179-180,236-252` and `P/views/dock/layout.rs:94-133` put Queued inside the dock, but `P/app/agent_view/render.rs:1011-1027,1878-1892` can still render the same queue by the composer when dock mode is off.
