### Notes

- “Overlay attached” is demonstrably a separate mode today: `DashboardReturn::{Agent,Overlay}`, `attached_agent`, `When::DashboardOverlay`, and a special input cascade are independent from `ActiveView::Agent`. The dashboard itself is a separate `ActiveView::AgentDashboard`; deleting session overlay distinction does not require deleting the dashboard. Preserve `Ctrl+\\` toggle and dashboard return target; do not use attachment to select session rendering/key context.
- Entry paths: startup/new session and `--resume`/picker/M1 switcher establish/select an agent without dashboard attachment; dashboard-entered main sessions attach it. All main sessions otherwise use `AgentView::draw`. Child takeover currently differs regardless of how the child was opened. Full takeover differences (status/header/hints, F6, focus, composer, key filtering, mouse and q/Esc) are enumerated in design §2 #5–#16; this table adds the missing path-1-vs-path-2 overlay split and ownership.
- Toast/focus should follow `active_view` uniformly, not the parent or a frame. Mouse session navigation should switch active view; dashboard remains a distinct destination. Status line should remain active for every session.
- Planned ownership: W2-A store/role and redirection substrate; W2-B child ACP routing; W2-C replay/eviction and row/link navigation; W2-D actions, session cycling, dashboard attachment/return and dispatch; W2-E rendering, hints, status line, input, focus and mouse chrome. W1-P is the already planned cycle fix dependency. No repository files were modified and no builds were run.
