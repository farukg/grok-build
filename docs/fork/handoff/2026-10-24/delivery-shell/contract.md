## Live Steer visibility contract (current source observation)

Confirmed Shell defect: projected Steer currently emits NO local live ACP notification to Pager. `session/acp_session_impl/parent_message.rs:404–499::drain_parent_messages_at_safe_point` sends `PersistenceMsg::Update(SessionUpdate::Acp(...))` directly and pushes ConversationItem::agent_message, but never calls send_update, emits SessionEvent::Notification, or forwards to the gateway. Persistence's queue_acp_sync only handles remote/relay sync, not the local Pager gateway. Thus a handler test expecting a live child event would currently be synthetic; the failure is upstream of Pager's ended-prompt filter.

Exact persisted event at parent_message.rs:450–460: ACP UserMessageChunk with TextContent containing the message text verbatim; ContentChunk._meta = {modelId: current child model}; SessionNotification.session_id = self.session_info.id (actual CHILD session); SessionNotification._meta = build_notification_meta() = {eventId: generated child event id, agentTimestampMs: current UTC ms}. NO promptId, turnStartMs, streamStartMs or isReplay is stamped by this path. The metadata is computed once per drain batch, so messages in that batch currently also share eventId/timestamp; this must be addressed when wiring live notification, otherwise event-id dedup may drop later messages. These ACP events are submitted to child updates.jsonl persistence (subject to existing merging); child chat history gets corresponding SyntheticReason::AgentMessage conversation items. The admission receipt identity parent-message-<messageId> is NOT the notification promptId.

Canonical send_update_full (updates.rs:255–325) instead generates eventId per call, stamps current_prompt_id (the active child turn, NOT admission receipt prompt id), streamStartMs/turnStartMs from child chat-state notification meta when present, agentTimestampMs, totalTokens, and optional chunkId. isReplay is absent for ordinary send_update; only replay calls set true. It sends SessionEvent::Notification through event_tx; replay buffer → emit_buffered → emit_notification_direct owns live forwarding and persistence. A repair must reuse that pipeline without also retaining the direct persistence write (duplicate events), and preserve existing transactional safe-point/teardown invariants. No source change is made for this read-only contract request.

## Completion/caller contract

Shell contract being implemented: additive serde-defaulted SubagentProgress fields `completion: SubagentCompletion` and `caller: SubagentCaller`. SubagentCompletion is defined in shell extensions::notification with camelCase variants `Working` (default), `Settling` (initial turn ended, admitted receipts still pending), `Pending` (initial turn and all admitted receipts settled; completion withheld). It does not duplicate delivery policy. SubagentCaller is defined/reexported by tools task::coordinator with camelCase variants `NotWaiting` (default), `Waiting`; coordinator derives it from live foreground reply or blocking query waiters, not child activity. Pager should store these observations on SubagentAttemptInfo, preserve through progress, reset on new/terminal attempt; show manual+caller blocked when delivery == Held && caller == Waiting, and distinguish Pending from Working/Settling. Shell publishes watch changes immediately over existing progress path. No Pager files will be edited by Shell owner.
