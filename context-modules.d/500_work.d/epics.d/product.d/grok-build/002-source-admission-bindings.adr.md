# Admission-backed input and output source associations

## Context

Chat-state already owns AppliedAppend and occurrence admission. Shell's generic requestInput association was gateway-only. Strict completion/delivery/batch projections discarded actual sources, including authoritative retained receipts. Output recording was fire-and-forget, and request/channel streams could contain several provider items. A caller prompt, text equality, a history index, or a publication claim cannot identify those items or prove that an echo exists.

The recoverable pre-edit source and source-derived capability inventory are `/tmp/grok-build-lead-20261027/source-binding-baseline/{source.tar,capabilities.md}`. No Git mutation or baseline capability removal is part of this transaction.

## Decision

- Extend existing output commands with `MutationReply::{Unobserved,Observed}`. Their existing mutation/accounting/deduplication implementations return the AppliedAppend from admission. Handle `push_{assistant_response,tool_result,model_output,unreported_model_output}_and_ack` preserves `MutationAdmissionError::{MailboxClosed,ReplyLost}`; no source is assigned by an observer. Assistant admission remains before local tool execution, never an excuse to run tools earlier.
- `InputProjection::receipt_identity` classifies actual receipt metadata once into `InputReceiptIdentity::{Completion,CompletionToolResult,Notification,Delivery}`. `CompletionProjectionAck::{AlreadyPresent,Continue}` carries `ReceiptSources { retained,missing }`: every retained source has its original receipt identity, including original tool-call or notification-batch identity. A retry combining receipts from several already-persisted items must not collapse them to its discarded candidate's single source. The outer MutationAck preserves AppliedAppend for a single proved source and names single-source unavailability otherwise; Shell consumes the inner authoritative receipt groups for multi-source reconciliation. Committed/NotCommitted/Indeterminate and their IO causes are preserved.
- Completion and notification reconciliation reuse their existing complete-JSONL receipt decoding/read transaction. Delivery keeps its binding-only validation/recovery scope and forwards an optional proved source from the same scan. Missing or malformed old source fields never mint identities. Compacted receipts with no retained receipt-to-item proof explicitly identify missing bindings. LegacyNormalized is not admitted-source proof.
- `StrictSourceOrigin` is the session-scoped wire projection of actual receipt identities; ordinary tool results use their actual tool-call identity. Strict source observations never use the current generic human prompt. `StrictInputRef` is a separate UI reference: Delivery ID, Notification batch ID, or an explicitly aggregate completion set. Offered notification completions are not claimed as admitted receipts. `TerminalInputProjection::{NotApplicable,Applied,AlreadyPresent}` forwards identities already resolved by the terminal admission owner, including fallback lookup, without another disk lookup or another admission. Parent-message echoes reuse their maintained delivery-ID owner. Preprojected strict inputs no longer emit the superseded generic requestInput/StrictReceiptSourceUnavailable placeholder; their echo carries only its real strict receipt reference. Generic human/harness requestInput and AppliedAppend behavior remains unchanged.
- Responses' existing converter retains provider message/function-item/tool-call references in an opaque, serde-skipped `AssistantItem.output_origin`. Its single canonical Assistant can aggregate several provider output items, so the reference is explicitly aggregate. Shell snapshots it before mutation and clears it before canonical admission; it is not carried into model requests or repeated history clones. Existing Reasoning and backend-tool IDs remain their structural owners. Existing parser ChannelToken gains OutputOrigin only; exact-body capture and Preview extraction are unchanged. Responses uses authoritative item IDs; Messages preserves its provider message ID as an explicitly message/channel aggregate. Backends lacking per-item/message IDs use named request/channel aggregates, never fabricated IDs. Fallback text retains the same authoritative item/aggregate reference when available.
- Accepted output observations carry the original sampler RequestId returned by `SamplerTurnOutcome::Response`, not a later current request. They contain actual ACK bindings, with vectors for honest channel aggregates and original provider references for item/aggregate origins. They describe admitted contributions, not completeness of streamed bytes: rejected retries, partial/unadmitted streams and absent final provider items may have no source. A request/channel aggregate must not be reinterpreted as a per-item or per-row source, even if only one admitted contribution is currently known.
- `_meta.requestOutput` uses `StreamOutputOrigin::{Unknown,Known,Aggregate}`. Existing live and persistence text mergers preserve every distinct known structural origin and count unidentified merged contributions. They keep their text concatenation, annotations, buffering, write batching and Thinking/Tool chronology; only binding metadata changes. Equal origin metadata takes the existing fast path. Neither merger searches bodies or creates identities.
- Persist `SourceBindingObservation::{Input,Strict,Output}` as additive `SessionUpdate::RequestSourceObserved` through existing `AppendUpdatesAndAck` and SessionUpdateEnvelope. Generic input observations retain their original exact PromptInputRef coordinates and live `x.ai/session/request_source/applied` event. Strict/output live events use `x.ai/session/request_source/observed`. Cold replay recovers the typed observations without admitting another item. The observation is queued independently of gateway availability, but is not advertised as durably written merely because it was queued or forwarded. It is not a publication claim: it has no top-level `_meta.requestSource`, never proves an echo exists, and never creates a UI/model message. The existing diagnostic owner retains typed persistence failure/progress and optional-failure isolation; its ACK is not relabeled as source-history durability or provider dispatch.
- All source publications retain `UnconfirmedIndependentHistoryChannel` and Unknown content evidence. New typed binding/reference Debug is opaque; provider serializers and canonical Assistant serde cannot expose the structural reference metadata. No request-capture claim/retention/recovery, raw capture, serializer, Preview producer, storage replay cursor/filter, Pager or navigation owner is replaced.

## Consequences

Consumers join requestInput only to an actually present matching input echo, strict refs to exact admitted receipt identities, and provider references to the matching output observation. Aggregate reference sets and vectors of retained/accepted sources remain aggregates; missing parts stay unknown. Prepared membership, transformations, dispatch, body equality and source-history durability remain separate evidence. No association implies sent, provider consumption, a durable human echo, or an unchanged original body.

There is no polling, new startup I/O, UI-frame work, extra model call or early local tool execution. Existing scans are reused and existing text batching is retained. Actual output ACKs add one existing actor round trip per accepted item; diagnostic journal writes add source facts at admission/observation boundaries. Buffer metadata work is confined to the existing chunk merge window, with same-origin fast paths. Disk latency, backlog, aggregate metadata size and runtime ordering still require measurement.
