# Local request evidence and occurrence publication

## Context

The chat-state admission owner assigns occurrence IDs. The sampler owns exact post-provider serializer bytes and attempt lifecycle observations. These facts are not model-consumption evidence. Shell previously compared injected record bodies against a vector recreated for every turn, causing old synthetic history to be published repeatedly. Capture events were discarded.

A recoverable pre-edit source archive and source-derived replacement inventory are at `/tmp/grok-build-lead-20261027/request-publication-baseline/`. The serializer, source admission/normalization, Context authority and policy snapshot remain their existing owners.

## Decision

- `NotificationSender` owns session-lifetime `SourcePublications`. Existing canonical source IDs seed suppression without new startup I/O. First actual preparation lazily restores the durable source-claim ledger through the existing persistence FIFO. When the private ledger is absent, exact typed source metadata in the existing unfiltered update log reconstructs known publications; metadata-free legacy rows remain unbound. The next publication bootstraps those recovered IDs into the incremental ledger before appending new claims. Claim keys are occurrence IDs, never bodies or chronological positions. New admitted identical occurrences remain distinct. LegacyNormalized and unadmitted records are not retrospectively assigned UI identity.
- `prepare_request_for_sampling` preserves the built model request and its Context tool/schema gate. It emits only genuinely new admitted synthetic records. `ContextView` is diagnostics-only and is not republished into normal chat rows or inserted into model history.
- The existing `AppendUpdatesAndAck` rail durably appends publication claims before optional diagnostic updates. A claim means a publication may have applied, not that it reached a client. It survives compaction, restart, old-checkpoint restoration and lost replies. Optional write failures never enter the primary write-failure latch or consume an unrelated primary failure. No rollback is inferred from ReplyLost. A malformed/unavailable claim ledger disables uncertain row publication with a typed diagnostic; it does not stop inference or invent identity.
- `submit_turn_request` binds the sampler UUID to session, turn, generation and existing logical request coordinates before submission, via `BeginRequestCapture` on the same FIFO. `handle_sampling_event` consumes LocalRequest events even after live stream ownership has been cancelled. Prepared, local DispatchStarted, status-only ResponseHeaders and Finished remain separate ordered observations, including incomplete attempts. No headers are captured.
- `SessionPersistence` owns registration, capture writes, receipts and resident reads. Blocking file work runs on its existing serialized FIFO via `spawn_blocking`, not a second collector, client or global map. Capture failures do not affect its primary write-failure latch. Confirmed persistence carries its required immutable origin. The source-identity/history channel remains explicitly `UnconfirmedIndependentHistoryChannel`: a later update or flush acknowledgement does not prove a rewrite sent on another channel arrived. Capture never writes request-pruned history as canonical history or rewrites newer admissions.
- `request-capture-v1/` contains an incremental request-ID index, incremental source-claim ledger, atomically replaced per-request manifests, and a bounded raw/publication body cache manifest. Exact blobs are the original opaque serializer bytes. Request/attempt observations retain full producer membership, transform and direct/transitive compaction facts without interpreting retained IDs as verbatim bodies. PreparedBody always retains the observed original digest and length independently of availability, including oversize, expired, failed and unconfirmed captures. Unchanged retry bodies share one digest-addressed blob pair after exact-byte validation; public body reads validate both original and publication digests.
- Raw retention is per session: at most eight recent distinct body pairs and 64 MiB combined raw plus publication bytes, with an 8 MiB maximum original body. The small per-session limit avoids a new cross-session cache authority. This is not a claim of a global disk bound across arbitrarily many sessions; ordinary existing session retention is unchanged. Cache recency advances only on new Prepared observations. Oversize is explicit NotCaptured, never truncation. Only cache-manifest-owned generated blobs are evicted. Metadata, source claims, outcomes, conversation logs and unrelated files are not evicted by this policy. A durable Writing intent accounts for interrupted writes. Missing/corrupt evidence is Unknown/Unavailable rather than reconstructed payload; normal known eviction is Expired.
- Private files use the maintained atomic writer with a private creation mode, parent-directory sync, and existing owner-only directory creation. Unix modes are 0600 files and 0700 capture directories. Ordinary session artifact collection excludes the entire capture directory, including metadata; no GCS, trace or remote revival occurs.
- Public body reads expose only the producer's `publication_view()` representation with ExactLocalJson/Redacted plus the original digest. The stored publication digest is validated on read. ExactLocalJson means unchanged by the existing scrubber, not credential-free. `RequestBodyRead` has opaque Debug. A protected local reference contains only validated session/request/attempt/digest coordinates, not an arbitrary path. No exact-raw RPC is introduced.
- `x.ai/session/request_snapshot` offers typed List/Get/Body actions. Body selects LatestPrepared explicitly or a particular digest within an attempt. List is paginated, defaults to 50 and caps at 100. Resident reads use the existing persistence resource; cold reads use the maintained persisted-session locator and verify summary/session and snapshot/request identities. Neither path loads, resumes, starts or queues model work; cold reads open no actor channels. There is no polling, per-frame serialization, raw-body eager loading or startup capture-file read.
- `x.ai/session/request_snapshot/observed` carries typed snapshot reference, attempt observation and persistence receipt; top-level sessionId uses existing leader subscriber routing. New injection rows retain their existing protocol variant and carry typed source publication metadata in `_meta.requestSource`. No pager/renderer/geometry/navigation changes are part of P2. Existing metadata-free rows remain unbound rather than being text/index backfilled.

## Consequences

P3 can join new synthetic row source IDs with observed Prepared membership and independent DispatchStarted facts using `(sessionId, request UUID, attempt)`. Get restores the same evidence after restart. Absence of a membership, body or lifecycle observation remains unknown; Prepared alone is not sent, DispatchStarted is only local execution initiation, and no event proves provider/model consumption. Unknown or partial transform evidence never permits a verbatim label. Compaction replacement coverage and inherited sources are transported unchanged, not interpreted as summary fidelity.

Ordinary human/harness row binding still requires an admission receipt exposing its actual source together with the existing UI-admission identity. `xai-chat-state/src/handle.rs::push_user_message_and_ack` returns only `Option<()>`; `actor/mod.rs::PushUserMessageAndAck` discards the admitted item's identity in its unit reply. P2 exposes those sources in actual request membership, but cannot legitimately attach an old or new human UI row by text/index. That producer contract is a precise P3 prerequisite outside this Shell storage partition, not a guessed association added here.

There is one lazy ledger read per session's first actual preparation and bounded new-body disk work per actual capture; retries share raw files and no UI-frame work is added. Disk latency, event backlog and aggregate multi-session storage footprint need runtime measurement. Lightweight per-request evidence grows with actual observations and existing session retention, not a new global in-memory collector.

Authored, unexecuted regressions cover multi-turn publication, identical new occurrences, restore/legacy/request-only limits, durable claims after compaction/restart/checkpoint reintroduction, independent history-channel uncertainty, actual capture origin after cancellation, partial/failed/cancelled attempts, retry blob sharing, eviction/reference survival, missing data, oversize, private Debug/public redaction, publication hash integrity, optional failure isolation, upload exclusion and passive cold reads without session activity.
